### COMP-029: Bounded automatic transport recovery

The twelfth pass implements the plan's sixty-second grace for a brief eligible transport interruption. The original deadline is fixed across failed attempts. The server hides and suspends the dropped avatar, settles already accepted movement at a safe checkpoint, and retains one authenticated owner under the existing lease fence. Resume requires the original current cookie session and an allowed origin, advances connection generation, and sends fresh private/world snapshots before new input. Both the native WebSocket upgrade and manual SDK reconnect HTTP path are guarded; possession of a reconnect token alone is insufficient. Tokens remain in memory and are rotated/removed with their binding.

The client freezes shared movement, clears held controls and nearby avatars, disables SDK offline message buffering, and never replays movement or automatically resends an ambiguous Save. A pending Save retains its exact command ID, activity, revision and payload for the user's explicit **Retry save** after resynchronization. The server's private `worldActive` flag describes retained runtime membership; persisted `activity=overworld` alone cannot activate a profile-only connection. An interrupted Enter is not automatically submitted again. Explicit Leave, signout, replacement, terminal rejection and disposal stop local retries. An offline Leave cannot deliver a server command, so the hidden server reservation expires within its existing deadline.

Installed SDK 0.18.4 emits `onReconnect` before its JOIN acknowledgement, and its scheduled retry callback does not recheck `enabled`. The client defers hello until after acknowledgement and guards the public `connection.reconnect` method against cancellation/deadline expiry before opening another socket. It sets `maxEnqueuedMessages=0` and clears any queue on drop/resume. This is a bounded compatibility workaround, not a dependency patch or an offline-command mode.

Backend process loss and terminal/grace-expired recovery still require explicit fresh authenticated admission; an abrupt process loss can leave its prior lease active for at most fifteen seconds and may lose walking since the last checkpoint. No automatic fresh admission occurs. Existing ADMINA/ADMINB accounts and source content are unchanged. Private story overlays, live battle/script/trade continuations, broader latency/population tests and public deployment remain outside this change.
