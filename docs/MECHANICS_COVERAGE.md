## Twelfth-pass transport recovery — verified bounded scope

Eligible brief transport loss now has a fixed sixty-second grace without extending the deadline on failed attempts. The server removes the suspended avatar from shared presence, completes only already accepted movement/transfer work at a safe checkpoint, and retains the same authenticated character owner with lease/session fencing. Resume authenticates the original current cookie session, advances connection generation, resets input sequence and restores fresh authoritative snapshots. Native WebSocket resume and manual SDK reconnect HTTP requests are both guarded. Old input generations and stolen/expired/revoked bindings cannot obtain world authority.

The client labels recovery, freezes shared movement, clears held directions/Shift and remote avatars, and disables offline message queues. Resume requires a fresh private snapshot and, only when its server-owned `worldActive` flag is true, a fresh world snapshot. A profile-only transport therefore stays outside the world even when persisted character activity says overworld. No movement, Enter or ambiguous Save is automatically replayed. An uncertain Save retains its exact command ID/payload/revision for explicit **Retry save**; definitive errors are not converted into altered retries. Default walking, Shift running and integer camera/character anchors are preserved.

Explicit Leave, signout, replacement and terminal errors cancel browser retries. Offline Leave returns to anonymous preview but cannot notify the server immediately; its hidden reservation remains bounded by the original deadline. A lost backend process cannot retain the in-memory transport token or owner and requires fresh authenticated admission, potentially after the old lease expires within fifteen seconds. Recovery resumes a committed location, not unsaved walking. No fixture, account or asset changes are made to the existing ADMINA/ADMINB testing accounts.
